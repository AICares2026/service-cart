## Stack
C# / .NET; NuGet packages for dependencies; xUnit or MSTest test suite (exact versions undetectable from metadata)

## Constraints
Never modify:
- `*.lock` files (packages.lock.json, nuget.lock.json)
- `*.designer.cs`, `*.generated.cs`, `*g.cs`, any file with `// <auto-generated>` header
- Migration files: `Migrations/` directories, any file matching `*_Migration.cs` or EF Core migration snapshots
- Credential and secret files: `appsettings.*.json` containing connection strings, `*.pfx`, `*.pem`, `*.key`
- `global.json` (controls SDK version — changes break CI)
- `.github/` or any CI/CD pipeline definitions

## Conventions
- One `.csproj` per logical service layer (e.g. API, Domain, Infrastructure, Tests)
- Test project names end in `.Tests`; test files follow `<ClassUnderTest>Tests.cs`
- Test methods use `MethodName_Scenario_ExpectedResult` naming
- Production code lives alongside its `.csproj`; no flat src/ dump
- Dead code removal must not delete `public` members without verifying no external callers across all projects

## Dependency manifests
- `*.csproj` — all NuGet `<PackageReference>` entries live here; one per project
- `packages.lock.json` — do NOT edit; regenerated by `dotnet restore --locked-mode`
- `Directory.Build.props` / `Directory.Packages.props` — if present, central version overrides go here; edit these instead of individual `.csproj` files when they exist
